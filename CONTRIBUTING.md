# Contributing

This repository is at the documentation foundation stage. Discuss substantial work with the maintainer before implementation.

## Pull request expectations

1. Describe the goal, scope, and explicit acceptance criteria.
2. Keep the change focused and document its independent origin. Use only synthetic data and assets with clear reuse rights.
3. Add meaningful tests where behavior is introduced or changed, and report the exact checks run and their observed results. State any checks that could not be run. Never invent results.
4. Review the diff for credentials, personal data, generated outputs, and dependency directories; run a secret exposure scan.
5. Request independent human review, especially for AI-assisted changes. Do not merge without explicit human authorization.

See `AGENTS.md` for PASS / HOLD / FAIL gate criteria and `SECURITY.md` for private vulnerability reporting.

## Licensing

Contributions must comply with the applicable MIT license and the scope defined in README.md.

Contributors must have permission to submit their work under the applicable terms. Separate licensing decisions require explicit maintainer authorization.
