# Security policy

## Scope and data boundaries

This is a public, independent portfolio repository. Use synthetic data and independent implementations only. Do not access or reuse proprietary RQS Studio code, the private commercial RQS workspace, production credentials, customer data, or commercial RQS infrastructure. Do not commit environment files, private keys, tokens, dependency trees, or generated build artifacts.

## Reporting a vulnerability

Please report potential vulnerabilities privately to the repository maintainer through GitHub private vulnerability reporting, if enabled. If that channel is unavailable, contact the maintainer privately before public disclosure. Do not include working secrets or sensitive customer data in a report. Avoid public issues for exploitable details.

The maintainer will assess the report and coordinate a response. No response-time or support guarantee is offered at this stage.

## Before submitting changes

Review the diff and tracked files for sensitive information, run a secret exposure scan, and document the tool or method and result. A clean scan is not proof that no secret exists; manual review remains required.
